# T-02.2E.1A — authoritative membership registry foundation

Disposable PG16 only. The existing four-migration catalog tests run before 0005. Adds subject_scope keyed by subject/tenant/unit with globally unique immutable generation, monotonic bigint revision generated by trigger, active status, unique audited change reference, server timestamp and append-only change audit. A single owner-mediated transaction writes membership and audit; duplicate audit reference aborts the membership change. Changes serialize on a row; reviewed callers must use exact generation/revision CAS and require one affected row. Initial deactivation is terminal; re-enrolment/new incarnation requires a separately reviewed permanent history design rather than resetting or reusing generation. Revision exhaustion denies change; an overflow fixture is not yet qualified. Lookup role is separate and receives only six columns, no audit or write access. No scoped runtime access.

The administrative path is deliberately temporary: trusted migration login SET LOCAL ROLE cephas_owner, no new administrative login or SECURITY DEFINER routine. Owner is privileged and can modify DDL or directly insert audit rows; this is not independently tamper-proof audit or customer administrative authorization. No OIDC verification, principal enrolment, broker lookup integration, or dispatch freshness enforcement. Test subjects and change refs are synthetic. New tests cover duplicate/null generation, immutable scope, revision/timestamp tampering, privilege denial, duplicate audit rollback, explicit transaction rollback, primary read-only READ COMMITTED lookup, uncommitted-state invisibility, actual lock contention and CAS, terminal deactivation, deletion/truncate denial and independent scope. Need post-0005 complete manifest, separate approved admin path, overflow/re-enrolment design and production broker integration; R-05 remains open. No local PG16 execution claimed; CI pending. No production or independent acceptance or merge.
