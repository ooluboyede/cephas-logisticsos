## 1. Trust boundary and scope (A01 / F01–F04)

One directly authenticated restricted PostgreSQL login per tenant/business-unit pair. Database scope is anchored to SESSION_USER and a protected catalog-validated registry, not mutable custom settings. Subject is application-authenticated, not database-authenticated. Customer-controlled deployment, offline signed licensing separate from authorization. Preserve the R-26 bounded source scanner and trusted composition/adapter contract. SQL injection and same-scope arbitrary SQL, compromised broker holding multiple scope credentials, privileged administrators, infrastructure compromise, metadata/timing channels and revocation races remain residual risks. RLS does not replace SQL privileges.

## 2. Registry, approvals, issuance and lifecycle (F01)

Schemas security and ops owned by cephas_owner (NOLOGIN). Registry control identities are not application roles. The former generic provisioner is retired as a design concept: there is no single provisioner login with arbitrary binding write authority. Separate operator identities cephas_approver, cephas_issuer, cephas_activator and cephas_retirer; trusted customer DBA creates roles, controls the admission lock and administers these identities. Two distinct human approvals and review of intended tenant/unit are required in customer-controlled change control before cephas_approver records an approval. Separation assumes these credentials and operators are independently controlled. Privileged DBA/owner or colluding administrators can bypass the control and remain trusted.

All identifier columns use the F06 text domain below. Dedicated database per deployment; deployment identity pinned in configuration and approval records, no cross-deployment connection. The following relation/constraint and policy specification is intended DDL, not an executed migration.

- security.tenant: tenant_id PK.
- security.business_unit: (tenant_id,business_unit_id) PK, tenant_id FK. Registry provisioning uses dedicated controlled owner operation; no scoped runtime or lifecycle identity writes these relations.
- security.binding_approval: approval_id UUID PK; deployment_id, role_name name UNIQUE, role_oid oid, generation UUID UNIQUE, tenant_id, business_unit_id, approver_subject, change_ref UNIQUE, approved_at timestamptz, expires_at timestamptz, all NOT NULL; CHECK expires_at > approved_at; FK (tenant_id,business_unit_id) to business_unit; UNIQUE (approval_id,role_name,role_oid,generation,tenant_id,business_unit_id). Approval is append-only. It must be for a newly issued unique opaque login name, never a replacement scope for an existing login.
- security.role_issuance: role_name name PK, generation UUID UNIQUE, role_oid oid NOT NULL, approval_id UUID UNIQUE, deployment_id, tenant_id, business_unit_id, issued_at timestamptz, all NOT NULL; composite FK to approval matching approval_id,role_name,role_oid,generation,tenant_id,business_unit_id; UNIQUE (role_name,role_oid,generation,tenant_id,business_unit_id). Deployment_id must match pinned deployment and referenced approval. Permanent, append-only. No UNIQUE constraint on historical role_oid alone (OID reuse is possible).
- security.scope_binding: role_name name PK, role_oid oid NOT NULL, generation UUID UNIQUE, tenant_id, business_unit_id, state text NOT NULL CHECK state IN ('pending','active','retired'), created_at timestamptz NOT NULL, retired_at timestamptz NULL; CHECK ((state='retired') = (retired_at IS NOT NULL)); composite FK (role_name,role_oid,generation,tenant_id,business_unit_id) to role_issuance; FK to business_unit; partial UNIQUE (tenant_id,business_unit_id) WHERE state IN ('pending','active'); partial UNIQUE (role_oid) WHERE state IN ('pending','active'). Retired records retained forever. No role name, OID, generation, scope or creation timestamp can be updated by lifecycle identities. Role names unique per deployment lifetime (including restored generations); opaque <=63 ASCII bytes, checked against permanent external ledger. UUID generation unique; OID is only a cluster-local consistency check, not durable identity.

All control relations ENABLE and FORCE RLS. Define predicates:
- D(a): approval deployment_id equals pinned deployment (migration-provisioned literal, not custom setting), expires_at > statement_timestamp(), and exact tuple matches current pg_catalog.pg_roles entry by name and OID, with all restricted role attributes and expected membership graph verified by privileged admission controller. SQL predicate requires r.rolname=a.role_name AND r.oid=a.role_oid AND NOT r.rolsuper AND NOT r.rolbypassrls AND NOT r.rolcreaterole AND NOT r.rolcreatedb AND NOT r.rolreplication AND NOT r.rolinherit; creation/issuance requires NOT r.rolcanlogin; activation requires r.rolcanlogin. Membership graph is a separate mandatory transactional controller check, not implied by D.
- A(i): EXISTS matching unexpired approval a with all composite identity/scope fields and deployment equal to i, satisfying D(a) for issuance. No approval lookup uses caller-controlled settings.
- I(b): EXISTS exact matching issuance i (all five identity/scope fields) AND matching approval for i, satisfying D(a) for the requested transition. Registry insert requires NOLOGIN; activation requires LOGIN. All queries schema-qualified and refer explicitly to outer relation columns.
- B(b): b.role_name = SESSION_USER AND b.state='active' AND EXISTS (SELECT 1 FROM pg_catalog.pg_roles r WHERE r.rolname=SESSION_USER AND r.oid=b.role_oid AND r.rolcanlogin AND NOT r.rolsuper AND NOT r.rolbypassrls AND NOT r.rolcreaterole AND NOT r.rolcreatedb AND NOT r.rolreplication AND NOT r.rolinherit).

Policy matrix (each named command is a PERMISSIVE policy unless stated; no other policies or grants; no lifecycle role has membership in another):
| Relation / role | SQL privilege | USING | WITH CHECK |
|---|---|---|---|
| approval / approver | INSERT listed columns | n/a | D(new) with NOLOGIN, expiry and pinned deployment |
| approval / issuer, activator | SELECT | TRUE | n/a |
| issuance / issuer | SELECT | TRUE | n/a |
| issuance / issuer | INSERT listed columns | n/a | A(new) |
| issuance / activator | SELECT | TRUE | n/a |
| binding / issuer | SELECT | TRUE | n/a |
| binding / issuer | INSERT listed columns excluding retired_at | n/a | state='pending' AND retired_at IS NULL AND I(new) with NOLOGIN |
| binding / activator | SELECT | TRUE | n/a |
| binding / activator | UPDATE(state) only | state='pending' | state='active' AND retired_at IS NULL AND I(new) with LOGIN |
| binding / retirer | SELECT | TRUE | n/a |
| binding / retirer | UPDATE(state,retired_at) only | state IN ('pending','active') | state='retired' AND retired_at IS NOT NULL |
| binding / scoped_runtime | SELECT(role_name,role_oid,tenant_id,business_unit_id,state) only | B(row) | n/a |
| binding / scoped_runtime | RESTRICTIVE FOR ALL (no additional grant) | B(row) | FALSE |

For lifecycle write paths, add a RESTRICTIVE policy per applicable command/role with the same predicate as its permissive policy (including activation and retirement old/new constraints), protecting against inadvertent additional permissive policies. SELECT access to approval/issuance is limited to named trusted lifecycle roles; no runtime read. Approval and issuance have NO UPDATE, DELETE or TRUNCATE privilege for any lifecycle role. Binding has NO DELETE or TRUNCATE. Owner-only BEFORE UPDATE trigger rejects changes to identity/scope/created_at and invalid state transitions including active->pending and any transition out of retired; uses OLD/NEW and no privileged execution; approval/issuance BEFORE UPDATE OR DELETE trigger rejects mutations as defense in depth. No TRUNCATE grants; owner-only trigger rejects TRUNCATE on all three relations. Owner/DBA can alter triggers/policies and are explicitly outside guarantee. No SECURITY DEFINER path; no shared control-role login. No ordinary owner operational access: FORCE RLS and no ordinary owner policies. Migrations that require data maintenance must be separately approved and audited with no persistent bypass.

Lifecycle is fail-closed, serialized by deployment administrative controller (transaction advisory lock plus database uniqueness constraints; lock not security against privileged bypass). DBA reserves fresh name in external append-only, independently backed-up ledger before creating restricted NOLOGIN role. Approval binds exact deployment, scope, role name/OID and generation; approver cannot update it. Issuer creates permanent issuance row and pending binding in one transaction; no route until both commit. No login route if any step fails. DBA verifies catalog grants and secret vault readiness, sets LOGIN, activator independently verifies exact approved tuple and changes only pending->active. Broker independently verifies role, mapping, state and generation using trusted control-plane manifest before admitting. Activation expiry must be checked at admission, not an ongoing membership lifetime; after activation, binding remains active until retirement. If activation fails, disable login and retire; no reusing pending names with expired approval. No ability to remap existing login by UPDATE or retire/reactivate. Scope change or credential rotation uses a new role/generation after old scope is retired (no overlapping pending/active scope); availability interruption accepted. For retirement first block routing, disable LOGIN/revoke CONNECT in controlled DBA transaction, retire binding and terminate matching backends (verify zero by database and role identity); remove grants and retire credentials, preserve ledger/binding; drop role only after dependency check. Activation cannot proceed for a retired name. Audit actor, approval, deployment, tuple, transition, timestamp, outcome and backend termination evidence; no secrets. On failure quarantine scope, not fallback. Independent ledger contains every reserved name even if issuance never completes. On restore/clone block all broker access and validate external ledger; fresh names/generations/OIDs and rotated credentials only. Reconcile/retire all restored bindings before serving. Fail closed if durable ledger unavailable. Test role recreation, stale OID, immutable fields, missing approval, expired approval, duplicate issuance, retirement replay, ledger mutation/TRUNCATE and cross-scope remapping.

## 3. Operational RLS (F02)

Every scoped base table ENABLE and FORCE RLS. No views, SECURITY DEFINER routines, foreign tables, partitions or alternate paths in initial scope. Example intended minimal operational relation ops.scoped_entity: tenant_id, business_unit_id, entity_id identifier NOT NULL, payload non-scope field; PK (tenant_id,business_unit_id,entity_id), FK (tenant_id,business_unit_id) to security.business_unit. Runtime has schema USAGE, table SELECT/INSERT/DELETE and UPDATE(payload) only, no scope/key updates or registry writes.

Normative example policy expression P for ops.scoped_entity (expand identically per table with table-qualified columns; C collation explicit for settings):
```sql
COALESCE(
  pg_catalog.char_length(pg_catalog.current_setting('cephas.subject_id', true)) BETWEEN 1 AND 128
  AND (pg_catalog.current_setting('cephas.subject_id', true) COLLATE "C") ~ '^[A-Za-z0-9]'
  AND (pg_catalog.current_setting('cephas.subject_id', true) COLLATE "C") !~ '[^A-Za-z0-9._:-]'
  AND pg_catalog.char_length(pg_catalog.current_setting('cephas.tenant_id', true)) BETWEEN 1 AND 128
  AND (pg_catalog.current_setting('cephas.tenant_id', true) COLLATE "C") ~ '^[A-Za-z0-9]'
  AND (pg_catalog.current_setting('cephas.tenant_id', true) COLLATE "C") !~ '[^A-Za-z0-9._:-]'
  AND pg_catalog.char_length(pg_catalog.current_setting('cephas.business_unit_id', true)) BETWEEN 1 AND 128
  AND (pg_catalog.current_setting('cephas.business_unit_id', true) COLLATE "C") ~ '^[A-Za-z0-9]'
  AND (pg_catalog.current_setting('cephas.business_unit_id', true) COLLATE "C") !~ '[^A-Za-z0-9._:-]'
  AND scoped_entity.tenant_id = pg_catalog.current_setting('cephas.tenant_id', true) COLLATE "C"
  AND scoped_entity.business_unit_id = pg_catalog.current_setting('cephas.business_unit_id', true) COLLATE "C"
  AND EXISTS (
    SELECT 1 FROM security.scope_binding AS b
    WHERE b.role_name = SESSION_USER AND b.state = 'active'
      AND b.tenant_id = scoped_entity.tenant_id
      AND b.business_unit_id = scoped_entity.business_unit_id
  ), false)
```
Registry B independently filters this lookup; no recursive dependency. Restrictive FOR ALL TO PUBLIC USING(P) WITH CHECK(P); permissive SELECT TO scoped_runtime USING(P), INSERT WITH CHECK(P), UPDATE USING(P) WITH CHECK(P), DELETE USING(P). Additional permissive policy cannot widen scope, and absent permissive grant denies. Table-specific render and reviewed exact catalog expressions required before migration acceptance. Fail closed on unknown relation, unexpected owner, partition, view, routine, ACL or policy; manifest includes relrowsecurity, relforcerowsecurity, owner, columns, constraints, policy commands/roles/permissiveness/pg_get_expr normalized expressions and default ACL. Test extra permissive TRUE policy still denies foreign scope, plus manifest detects drift. Forced RLS does not constrain superuser/BYPASSRLS; RI checks bypass RLS, addressed in F06. No autocommit data access; parameterized transaction-local set_config; no raw user SQL or connection exposed.

## 4. Broker capacity and failover (F03)

Proposed limits, unmeasured: 100 active/pending scope pairs per dedicated deployment database. Two fixed broker slots, each <=40 physical sessions (active, idle and opening), <=2 per scope, <=20 idle total, zero minimum, lazy pools, bounded queue 100, checkout <=2 seconds, idle eviction <=60 seconds. Scope role CONNECTION LIMIT 4, defense in depth, not exact admission accounting. No external pooler until independently qualified to preserve directly authenticated SESSION_USER; no forced-user mode. Pool key deployment, verified database identity, role name, generation and secret version. Trusted connection broker alone owns connections and secrets, deployment-owned scope routing after verified TenantScope; request cannot select DSN/role/vault path. TLS verify-full, scoped vault permissions, no secrets to request code, no raw connection escape. Verify database identity, SESSION_USER and own active binding plus control-plane generation before use. Broker compromise may expose all deployment scopes; block routing, revoke vault access, retire/rotate affected credentials, terminate sessions, audit and requalify.

PostgreSQL 16 settings: max_connections=120, reserved_connections=15, superuser_reserved_connections=5. Ordinary slots=100: 80 broker + 20 non-broker (membership lookup 8, lifecycle 4 total, migrations 4, monitoring/ordinary operations 4). 15 reserved for separately authenticated emergency operations identity with pg_use_reserved_connections; 5 final slots for customer superusers only. No runtime or normal service has reserved role membership. Cap normal service login sources using per-source admission budgets and role limits; lifecycle four identities <=1 each; migration <=4, membership <=8, monitoring/normal ops <=4. No unclassified login source, dedicated server, restrictive pg_hba and CONNECT grants. Emergency roles explicitly inventoried, no routine use; reserved slots are admission classes, not a guaranteed idle count if privileged operators consume them. PostgreSQL connection limits are approximate; global server ordinary admission ceiling protects reserved classes, normal-source exact budgets depend on trusted admission and tested configuration. Validate actual settings, all login sources, effective reserved membership and load under churn; no claim of measured capacity.

Fencing mechanism deliberately favors safety over availability: no automatic broker or database failover in initial qualification. Fixed independent broker slot egress identities, customer-controlled network allowlist at DB and vault, one active replica per slot, separate per-slot vault access. Deployment controller serializes slot assignment and stores monotonic epoch in durable control-plane record. Replacement requires external infrastructure fence of old instance (revoke workload identity/vault access, deny its network egress and DB ingress, including established connections, stop/isolate old instance), privileged DBA terminates every session from old slot's dedicated source address and confirms zero sessions, verifies denied reconnect from old source, and records fencing evidence before enabling distinct replacement identity/address for same slot. Do not reuse egress address until verified old instance fenced. Broker process-local lease/epoch is not itself a fence; control-plane record alone cannot prevent SQL. No replacement if network fence, session evidence, control-plane consistency or identity separation unavailable; fail closed, no third replica. Database failover only after fencing old primary, recovery/revalidation of ledger and bindings, verified new primary identity, membership consistency and broker reauthentication; if split brain or uncertain, block writes and routing. Qualification tests simulate stale broker, failed fence, delayed termination, attempted reconnect and split brain. Capacity/fencing mechanisms are proposed deployment requirements, not implemented.

## 5. End-user membership and authorization freshness (F04)

Explicit guarantee choice: maximum 30-second AUTHORIZATION DECISION AGE at protected SQL dispatch and COMMIT initiation, not a hard physical transaction completion or commit deadline. This supersedes all earlier wording claiming transaction completion within 30 seconds. No promise of instant revocation or prevention of late durability after COMMIT was already submitted. Require owner and reviewer acceptance of this threat model. PostgreSQL 16 statement_timeout and idle_in_transaction_session_timeout are per-statement/idle protections, not a general transaction deadline.

Customer-configured OIDC issuer/audience, permitted algorithms, signature verification, expiry/not-before; stable local identity derived from verified issuer + subject, never email/client assertion. Authoritative membership table unique(subject_id,tenant_id,business_unit_id), active state, monotonic revision increment on every change; separately restricted membership lookup login and audited administrative change path. Read primary or synchronously consistent authoritative endpoint that guarantees latest committed state (initial target primary only), fresh READ COMMITTED transaction for each decision, never stale replica, old snapshot or positive cache. Fail closed on unavailability or ambiguous identity. Immutable broker-side decision binds credential validity, subject, scope, membership revision, monotonic check-start time and operation ID. Time age measured from before authoritative query, not response; if check age >=30 seconds or credential expired, deny.

Broker owns connection and all dispatch/commit, accepts only reviewed repository operations. Before checkout and transaction begin verify credential and exact active membership; before each protected SQL dispatch and immediately before COMMIT initiation read fresh authoritative membership again, require same active revision as transaction start, unexpired credential and total elapsed work-unit age <30 seconds from initial check. Never extend work-unit lifetime by rechecking. Revision change, revocation, lookup failure or elapsed deadline => no new SQL except cleanup, no new COMMIT, cancel/rollback, quarantine and discard connection. Revocation notification accelerates cancellation but correctness does not depend on delivery. Independent broker watchdog (separate from application callback) cancels on deadline; bound per-statement and idle timeouts as defense in depth; if cancellation delayed escalate via authorized customer controller to terminate exact backend, block new work and do not reuse. Race between final authoritative check and dispatch is acknowledged; check age is bounded, not atomic revocation. In-flight commit may succeed late or result unknown; no false success/rollback claim, return unknown outcome, quarantine connection, reconcile by durable operation idempotency record before retry, audit. No prepared transactions (max_prepared_transactions=0), no autonomous commits/raw SQL. Use short work units, chunk/recheck queued jobs at execution with verified worker identity and current subject/service membership; never carry cached authorization. T-03 implements identity/membership/revision/audit; T-04 implements broker/watchdog/transaction/outcome reconciliation and cleanup. Commit/WAL delay, cancellation, lost notification, primary failover, stale replica, expired decision, revision change and late/unknown commit tests mandatory; assert no new dispatch/commit after deadline, NOT impossible late durability. No production end-user authorization claim until both implemented and accepted.

## 6. Privilege matrix and integrity (F05/F06)

All non-bootstrap identities NOSUPERUSER NOBYPASSRLS NOCREATEDB NOCREATEROLE NOREPLICATION NOINHERIT. cephas_owner and scoped_runtime NOLOGIN; migration, membership, lifecycle and scope login roles LOGIN only when provisioned (scope initially NOLOGIN). Bootstrap DBA privileged external actor, never pooled. Only DBA administers roles, lifecycle credentials and grants; independent change approval. Migration -> owner WITH INHERIT FALSE, SET TRUE, ADMIN FALSE. Scoped login -> scoped_runtime WITH INHERIT TRUE, SET FALSE, ADMIN FALSE. No other memberships for those roles; group has none; lifecycle and membership identities have none. Emergency identity alone receives necessary pg_use_reserved_connections membership, separately inventoried; no operational role. Revoke PUBLIC CONNECT/TEMP on dedicated DB and unnecessary CREATE/USAGE on public/app schemas. Explicit per-role CONNECT/schema/object rights only, no broad defaults. Owner-only creation via reviewed migration SET ROLE/RESET ROLE. Revoke default PUBLIC EXECUTE globally and unnecessary default privileges for each permitted creator; inspect schema-specific defaults. No runtime DDL, TRUNCATE, REFERENCES, TRIGGER, GRANT OPTION, privileged role ownership or alternate privileges. Catalog exact allowlist for attributes, owners, direct/transitive membership edges and options, default ACLs and effective privileges; test direct real logins, pg_has_role MEMBER/USAGE/SET, has_*_privilege, SET ROLE, SET SESSION AUTHORIZATION, DDL, future object privileges and policy mutations. Privileged DBA/owner trusted; migration credentials not available to application.

Identifier domain: NOT NULL text COLLATE "C", CHECK (char_length(value) BETWEEN 1 AND 128 AND value ~ '^[A-Za-z0-9]' AND value !~ '[^A-Za-z0-9._:-]'). Apply to all subject/tenant/unit/entity identifiers (not role OID/name or UUID control-plane IDs). Equivalent to Python fullmatch [A-Za-z0-9][A-Za-z0-9._:-]{0,127}. Test positive and negative Python/SQL vectors including trailing newline, whitespace, Unicode, punctuation-first, empty and boundary length. All scoped operational PKs, unique constraints, association keys and FKs include both scope columns; no global operational uniqueness; scope-aware upserts only, no client conflict targets. No scope update rights. RI bypasses RLS; normalize errors, never expose foreign identifiers/constraint names; test paired existing/nonexisting foreign IDs, cross-scope links and upsert conflicts. Timing/error channels not eliminated. Complete per-table manifest and integration evidence mandatory.
