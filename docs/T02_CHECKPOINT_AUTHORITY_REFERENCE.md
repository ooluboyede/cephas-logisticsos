# T-02.2C.2B.2C — independent checkpoint authority reference

Stacked on PR #19 at edeef0fa271d3e13c9848f38838e261d310e112e (CI #260 both jobs passed, 157 existing tests plus 18 engineering reference tests). Controlled non-production only. Adds a separate reference authority ledger and Ed25519 key, signed read/append receipts bound to namespace, operation, fresh 256-bit challenge and exact checkpoint. Client pins the authority public key, verifies each response, requires the expected successor, and independently re-reads the authority after a local reservation and compare-and-append. Both stores enforce name and generation non-reuse. Admission evidence requires the anchored exact reservation plus two valid human-key signatures against a trusted primary tuple/digest and current trusted time. This method produces no role, route, credential or authorization token.

Trust boundary: the local test authority is an in-process reference using another SQLite file, not a deployed independent service. Independent key custody, authenticated transport and write authorization, external anti-rollback storage, durable backup, operator separation and recovery must be qualified. A signer whose own store is rolled back can sign a fresh challenge with an old checkpoint; challenge binding prevents receipt replay but does not prevent rollback of the authority itself. Simultaneous rollback of both stores is outside this reference's guarantee. A crash after local append and before authority confirmation leaves divergent stores and blocks use; no automatic resynchronization, ledger reset or replay of role creation. A lost response after both appends requires explicit independently verified reconciliation. A successful reservation check does not grant an exactly-once creation capability; the external issuance controller must atomically coordinate role creation and preserve tombstones. A successful evidence check is not sufficient to enable a route; actual resource-side fencing, primary state, expiry recheck and external human enrolment are required. R-01/R-03 remain open. No new infrastructure provider selected without owner/customer deployment requirements.

Tests exercise anchored evidence, restart, local unconfirmed append, restored local copy, missing authority, stale predecessor, duplicate and wrong deployment, replay, wrong key and tampered checkpoint. Existing migrations, application source and R-26 unchanged. Existing CI automatically collects new engineering tests. No local execution claimed; pending exact-head CI. No production or merge authorized.
