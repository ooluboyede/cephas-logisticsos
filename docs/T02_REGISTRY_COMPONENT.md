# T-02.2C.1 — registry database component (partial)

Non-production only, stacked on PR #14. Migration 0002 adds three owner-controlled registry tables, composite deployment/approval/issuance constraints, immutable and terminal transition triggers, exact restricted column grants, forced RLS and restrictive lifecycle write guards. A digest and two distinct subject identifiers are structural evidence fields, NOT verification of two human approvals. The deployment literal and fixture credentials are test-only. The retirer may update state only; trigger generates retired_at. Role name reuse is rejected by retained issuance PK, and active runtime lookup also validates current OID and role attributes. Runtime sees five binding columns only, not approvals or issuance. No operational data access introduced.

The new tests reuse the three disposable B logins after foundation checks, authenticate each lifecycle role separately, exercise pending/active/retired transitions, wrong-column/privilege denials, stale-name recreation and restrictive read invariants. Database CI is not executed locally. This is not a complete lifecycle qualification: controller-level serialization across network/vault/routing, independently verifiable two-human evidence, external ledger, admission-expiry and race/fencing tests, exact policy/ACL manifests, restore/rotation and operational RLS remain required. No production or independent acceptance claimed. R-01–R-09 remain open.

The test-only bootstrap can alter roles and policies; privileged actors remain outside the guarantee. A retired binding does not instantly kill existing snapshots. Controller termination and route fencing are mandatory in later work.
