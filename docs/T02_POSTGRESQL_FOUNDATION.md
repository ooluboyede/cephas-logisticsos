# T-02.2B — initial disposable PostgreSQL 16 foundation

Status: partial implementation, not acceptance. Stacked on Draft PR #13, itself unmerged. This initial migration is deliberately restricted to a disposable dedicated PG16 cluster/database named cephas_t02_test; database-name and version checks are safety guards, not proof of environment isolation. No production execution, customer data or credentials. No application persistence path introduced.

0001_foundation.sql creates the owner/group, migration/membership/lifecycle and registry-admin identities with no passwords, limited role memberships, explicit schema and database grants, owner default privilege revocation, C-collated identifier domain and tenant/unit metadata tables with FORCE RLS. Scoped test logins are fixtures only, not issued production bindings. Only registry admin can read/insert tenant/unit metadata; runtime has no data grants or operational tables. Database roles are cluster-wide: isolated cluster and authentication configuration are mandatory; no claim of isolation from other databases in a shared cluster. Bootstrap is a trusted external superuser. Repeat migration rejects rather than silently altering existing roles; no general upgrade/rollback claim.

Tests run against an isolated postgres:16 GitHub service, no published host ports, explicit TCP SCRAM for actual fixture logins, independent random fixture-only passwords and a negative cross-role password test. Local bootstrap socket trust is limited to disposable service. CI fails if database/container unavailable or a test fails. Record server version, commit and migration hash. Existing Python job unchanged from A. Service tag resolves at runtime; digest pin and full qualification remain future requirements. New job is not yet a required ruleset check; administrator must add exact check before implementation acceptance.

This is a B foundation subset: F01 registry/approval/issuance/binding policies and external controller (C); operational scoped tables and complete manifest (D); membership, driver freshness and idempotency (E); capacity/fencing/recovery (F); full adversarial qualification (G). Test coverage here is metadata/role/default-privilege denial and identifier/constraint smoke tests, not proof of tenant/BU operational isolation. No R-01–R-09 declared closed. Initial DBA allocation proposal for F: at most two DBA sessions within five superuser-reserved slots (other three remain for emergency superuser use); actual server caps, admission controls and settings not implemented or verified in B. This service does not test the 120-connection capacity model. No automatic failover.

Preserve R-26 source/tests. Requires exact-head CI, qualified independent reviewer and protected promotion. No merge authorized.
